# AI Sana MVP

Бизнес превращает короткое описание проблемы в задачу для студентов:
черновик → уточняющие вопросы → карточка → рейтинг готовности → общий каталог →
предложения команд → ручное решение бизнеса. Геймификация мотивирует улучшать
постановку задачи; рейтинг не оценивает известность компании и не ранжирует команды.

Документация сверена с кейсом HackAlem AI «Геймификация практических заданий»,
разделы 2–5 и 9–11, и требованиями роли к шагам 1–7. По кейсу бизнес вправе выбрать
одну, несколько или ни одной команды; низкий рейтинг не запрещает публикацию и отклик.
Заглушка ИИ допустима при показе промпта, форматов и обработки некорректного ответа.

**Текущее состояние:** backend PHP/SQLite работает и покрыт тестами. Frontend пока
использует LocalStorage: `api.js` не вызывает HTTP API, а `business.js` считает
баллы по длине текста. Это отличается от серверного рейтинга по подтверждениям.
Сквозная интеграция UI → API → SQLite ещё не завершена. Открытые работы и приёмка —
в [INTEGRATION_CHECKLIST.md](INTEGRATION_CHECKLIST.md).

## Архитектура проекта

Стек: PHP + SQLite, чистые HTML/CSS/JavaScript. Composer, npm и сборщик не нужны.
Backend и frontend — логические части; физических папок `backend/` и `frontend/`
в репозитории нет. Реальная структура:

```text
.
├── index.html                  # Frontend: точка входа
├── style.css                   # Стили
├── app.js                      # Экраны, формы и события
├── api.js                      # Сейчас LocalStorage; точка подключения fetch()
├── business.js                 # Демонстрационные вопросы и рейтинг
├── catalog.js                  # Демонстрационный каталог
├── team.js                     # Демонстрационные отклики и решения
├── db.php                      # Backend: подключение SQLite
├── schema.sql                  # tasks, cards, teams, proposals
├── rating.php                  # Формула, уровни, недостающие поля
├── ai_helper.php               # Внешний ИИ, fallback и валидация
├── seed.php                    # CLI: миграции и начальные данные
├── migrate.php                 # CLI: обновление существующей БД
├── lib/migrations.php          # Миграции с сохранением данных
├── api/                        # HTTP JSON endpoints
│   ├── _common.php             # Валидация, ответы, транзакции
│   ├── tasks.php               # Черновики
│   ├── cards.php               # Карточки, подтверждения, ИИ-действия
│   ├── questions.php           # Совместимый локальный маршрут вопросов
│   ├── generate.php            # Совместимый локальный маршрут сборки

│   ├── teams.php               # Профили команд
│   ├── proposals.php           # Предложения команд
│   └── choose.php              # Ручное решение бизнеса
├── data/                       # По 5 синтетических записей каждого типа
```

`database.sqlite` создаётся в корне и исключена из Git. `tasks` хранит исходный
черновик, `cards` — карточку, `teams` — профиль, `proposals` — предложение и решение.
Предложение связано с `card_id` и `team_id`. Семь полей рейтинга дополняются
метаполями `title`, `topic`, `need`, `interaction_format`, которые баллов не дают.

## Формула рейтинга

Источник истины — `rating.php`. Начисляется весь вес критерия только при непустом
тексте и соответствующем `*_confirmed = 1`:

```text
R = Σ (вес_i × заполнено_i × подтверждено_i), i = 1…7
заполнено_i = 1, если есть непробельный текст, иначе 0
подтверждено_i = 1 после явного подтверждения бизнесом, иначе 0
0 ≤ R ≤ 100
```

| Критерий | Поле | Вес | Что подтверждает бизнес |
|---|---|---:|---|
| Контекст и потребность | `context` | 20 | Что происходит сейчас и что нужно изменить |
| Данные и материалы | `data_materials` | 20 | Доступные источники, формат, объём |
| Ожидаемый результат | `expected_result` | 15 | Конкретный результат работы |
| Критерии успеха | `success_criteria` | 15 | Измеримая проверка результата |
| Ограничения | `constraints` | 10 | Сроки, технологии, доступы и границы |
| Пользователи | `users` | 10 | Для кого создаётся решение |
| Связь с бизнесом | `business_contact` | 10 | Ответственная роль, консультации и обратная связь |
| **Всего** | | **100** | |

Флаг подтверждения называется `<поле>_confirmed`. Потребность раскрывается в
`context`, даже если есть отдельное `need`. Для публичной ИИ-карточки связь —
роль/отдел и порядок консультаций без личного email, телефона или ФИО:
это дополнительное требование нашей реализации.

| Баллы | Название по кейсу / для экрана | Значение `readiness_level` в API |
|---|---|---|
| 0–39 | Черновик | `проект` |
| 40–69 | Рабочая | `в работе` |
| 70–89 | Готовая | `готово` |
| 90–100 | Приоритетная | `приоритет` |

Заполненная ИИ карточка стартует с 0: все подтверждения равны 0. При подтверждении
полей в порядке таблицы рейтинг растёт `0 → 20 → 40 → 55 → 70 → 80 → 90 → 100`.
Пустое или неподтверждённое поле не даёт баллов. Смысл и достоверность сведений
проверяет бизнес; число баллов само по себе не доказывает реализуемость проекта.

`PATCH cards.php` атомарно сохраняет текст, подтверждение и рейтинг. Для сохранения
чернового значения передавайте `confirmed:0`, для подтверждения — `confirmed:1`;
по совместимости отсутствие флага тоже означает 1. Ответ содержит `rating`,
`readiness_level`, `rating_details.breakdown` и `rating_details.missing_fields`.
Frontend должен показывать их после ответа PATCH без перезагрузки страницы.
Текущий расчёт по длине текста требуется заменить.

## Правила каталога

Публикация — отдельное ручное действие после просмотра карточки:

```http
PATCH /api/publish.php
Content-Type: application/json

{"card_id":6,"published":1,"confirmed":1}
```

Нужны непустые `title` и `context`. Здесь `confirmed` означает просмотр всей
карточки: он не подтверждает семь критериев и не добавляет баллы. Порог рейтинга
отсутствует. Опубликованная карточка с 0–39 баллами видна всем командам и должна
отмечаться на экране как требующая уточнения. Неопубликованные карточки скрыты.
Изменение текста или подтверждения снимает карточку с публикации до повторной
проверки; повторный PATCH без изменения данных публикацию сохраняет.

`GET /api/catalog.php?sort=rating&topic=кафе&level=приоритет`:

- только `published=1`, без ограничения по «подходящим» командам;
- сортировка `rating DESC, id ASC`, в том числе по умолчанию;
- `topic` — поиск подстроки без учёта регистра в названии, теме, потребности и
  шести содержательных полях, исключая контакт бизнеса;
- `level` — точное значение API из таблицы уровней; фильтры сочетаются и сбрасываются;
- параметры кодируются через `URLSearchParams`; другие сортировки API не поддерживает.

Любая команда может откликнуться на любую опубликованную задачу; число откликов
не ограничивается. Предложение содержит идею, план, срок `YYYY-MM-DD` и
HTTP/HTTPS-ссылку на прототип (API допускает пустую ссылку). Начальное состояние:
`pending`, `chosen=0`.

Бизнес сравнивает предложения и **сам нажимает** «Выбрать» или «Отклонить».
`PATCH choose.php` с `proposal_id` и `decision` принимает `accepted`, `rejected`
или `pending` для отмены. Другие предложения не сбрасываются: можно выбрать одну,
несколько или ни одной команды. ИИ, рейтинг и публикация не назначают исполнителей.
API пока не проверяет личность/роль отправителя: явное действие UI не заменяет
серверную авторизацию владельца бизнеса.

## Роль ИИ-модуля

`generateQuestions()` выявляет пробелы и возвращает минимум три вопроса.
`buildCardFromAnswers()` переносит ответы в JSON ровно с семью основными полями.
Неизвестные значения пустые; черновик становится `context`, если нет отдельного
ответа. Факты, числа и отрицания сохраняются дословно.

Основной маршрут: `POST cards.php` с `action:questions`, затем `action:build`.
С `AI_API_KEY` вызывается внешний API через cURL; без ключа/cURL, при ошибке,
тайм-ауте или невалидном ответе включается fallback по ключевым словам и полноте.
Промпты находятся в `ai_helper.php`; вход/выход и примеры — в [AI_HELPER.md](AI_HELPER.md).

ИИ не придумывает факты, не подтверждает поля, не публикует, не начисляет баллы
и не выбирает/не рекомендует команды бизнесу. `validateAiOutput()` проверяет
схему, исходные ответы, признаки личных данных и выбора команд. Эвристики могут
ошибаться; итоговый текст проверяет человек.

Сохранены `questions.php` / `generate.php` с `localAssistant()`: они всегда локальные,
поддерживают ещё четыре метаполя и имеют отдельную валидацию, не равнозначную
`validateAiOutput()`. Для требуемого ИИ-потока используйте действия `cards.php`;
совместимые маршруты проверяются отдельно, без двойного создания карточки.

## Как запустить локально: backend и frontend

Нужны PHP с `pdo_sqlite` и браузер. Синтаксис совместим с PHP 7.3+; проверки
выполнены на PHP 8.4.26. Для внешнего AI нужен cURL, для HTTP-тестов — Python 3.
Ключ для запуска демонстрации не требуется. Из корня репозитория:

```powershell
php -v
php -m
$env:AI_API_KEY = ''
php seed.php
php -S localhost:8000 -t .
```

В модулях должен быть `pdo_sqlite`. Если PHP отсутствует в PATH, но есть XAMPP,
замените `php` на `& 'C:\xampp\php\php.exe'`. Для обновления существующей базы
без seed: `php migrate.php`. `seed.php` применяет миграции и добавляет по пять
записей только в пустую БД; повторный запуск сохраняет данные и решения бизнеса.

Откройте frontend: **http://localhost:8000/**. Этот же PHP-сервер раздаёт HTML,
CSS/JS из корня и обслуживает backend; отдельный frontend-сервер не нужен.
Проверка API: **http://localhost:8000/api/catalog.php?sort=rating**.

Сейчас UI хранит данные в LocalStorage (`ai-sana-demo-v1`), а API — в SQLite.
Одинаковый адрес сервера не синхронизирует эти хранилища. Очистка браузерного
демо не очищает SQLite; seed не обновляет LocalStorage. Связку ещё нужно завершить.
Для внешнего AI задайте `AI_API_KEY` в окружении PHP и перезапустите сервер.
`AI_MODEL` необязателен; `.env` автоматически не читается. Не храните ключ в коде/frontend.

## Тестовые сценарии

| Сценарий | Действия | Ожидаемый результат |
|---|---|---|
| Слабый черновик → дозаполнение → публикация | Ввести «Нужен прогноз продаж кафе»; получить ≥3 вопроса; заполнить и подтвердить поля; задать название; опубликовать | До подтверждений 0; далее 20, 40, 55, 70, 80, 90, 100. Видны пробелы. После публикации карточка доступна в каталоге |
| Отклик → сравнение → выбор | Две команды отправляют предложения; бизнес сравнивает идею, план, срок, прототип и явно принимает одно | До клика оба `pending`, `chosen=0`; после клика меняется только выбранное. Можно отклонить второе, принять оба либо не выбрать никого |
| Невалидный ввод | Пустой/пробельный черновик, неверный JSON, неизвестный id, неправильное поле, дата/ссылка; в ИИ-потоке — email | 400/404/422 по причине; сообщение пользователю; нет частичной записи и падения; UI сохраняет введённый текст для исправления |
| Границы рейтинга | Заполнить все поля без подтверждения; подтвердить все; снять подтверждение context | 0 → 100 → 80; пустое поле не даёт баллов даже при ошибочном флаге в тестовой БД |
| Низкий рейтинг и открытый каталог | Вручную опубликовать карточку с 0 баллами и названием/контекстом; сбросить фильтры; отправить отклик | Карточка видна, отклик разрешён; оценка влияет на позицию, а не право участия |
| Отказ внешнего AI | Отключить ключ; в тестовом транспорте подать HTTP-ошибку, отказ или повреждённый JSON | ≥3 вопроса, семь полей, неизвестное остаётся пустым; нет автоматического выбора; срабатывает fallback |

```powershell
php -n tests/ai_helper_test.php
php -n tests/ai_transport_test.php
php tests/rating_test.php
python tests/api_test.py
python tests/ai_api_test.py --php php
```

Если PHP вне PATH, для `api_test.py` задайте `$env:PHP_BINARY` полным путём,
для `ai_api_test.py` передайте его через `--php`. `-n` позволяет транспортному тесту
подменить cURL без платных запросов. HTTP/SQLite-тесты работают с временными
копиями приложения и отдельными базами, не меняя рабочую БД. Они не заменяют
два браузерных прогона после интеграции. Результаты — в чек-листе.

## Защита и файлы этой роли

План защиты и подготовленные ответы — [DEMO.md](DEMO.md). За 5 минут показывается
одна задача: уточнение, объяснимый рост рейтинга, открытая публикация, два отклика
и ручное решение. Баллы за прогресс студентов и проектный трекер не реализованы;
по разделу 7 кейса для демонстрации достаточно отклика и решения бизнеса.
Регистрация, чат, уведомления и обучение модели в текущий объём не входят.

| Ответственность роли ИИ / интеграция / документация | Файлы |
|---|---|
| ИИ, fallback, проверки и контракты | `ai_helper.php`, `AI_HELPER.md`, `prompts/card_assistant.txt` |
| Совместная интеграция backend | `api/cards.php`, согласование `api/questions.php` и `api/generate.php`, `API.md` |
| Проверки ИИ и его HTTP-потока | `tests/ai_helper_test.php`, `tests/ai_transport_test.php`, `tests/ai_api_test.py` |
| Документация, защита, приёмка | `README.md`, `DEMO.md`, `INTEGRATION_CHECKLIST.md` |
| Запуск UI | `index.html` — пути ресурсов; подключение `api.js` и экранов совместно с frontend-разработчиком |

БД, рейтинг, каталог и решения — зона backend-разработчика; экраны и события —
frontend-разработчика. Эта роль согласует контракты и проверяет прохождение данных.
Полная авторизация потребуется перед публичным запуском; встроенный PHP-сервер
предназначен для локального демо.
