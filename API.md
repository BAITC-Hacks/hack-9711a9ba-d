# AI Sana: backend API

## Запуск и обновление

Требуются PHP 7.3+ и pdo_sqlite. Из корня проекта:

```powershell
php seed.php
php -S localhost:8000
```

seed.php создаёт или обновляет схему. В пустую БД добавляется по 5 записей каждой
сущности. При наличии хотя бы одной записи seed пропускается. Для обновления
существующей БД без демо-данных: `php migrate.php`. Повторная миграция безопасна;
существующие данные, идентификаторы и принятые предложения сохраняются.
Миграция версии 1 также исправляет рейтинг пустых подтверждённых полей и
синхронизирует статус черновика с наличием опубликованных карточек.

Если php отсутствует в PATH:

```powershell
& 'C:\xampp\php\php.exe' seed.php
& 'C:\xampp\php\php.exe' -S localhost:8000
```

База database.sqlite находится рядом с db.php. seed.php и migrate.php доступны
только через CLI. Каталог: http://localhost:8000/api/catalog.php.

## Общие правила

POST/PATCH принимают JSON-объект с Content-Type: application/json. Ответы и ошибки
всегда JSON; списки — массивы, отдельные сущности — объекты. Создание — HTTP 201,
чтение/изменение — 200. Ошибки: 400 (валидация), 404 (нет записи), 405 (метод),
409 (неопубликованная карточка), 500 (внутренняя ошибка), 502 (невалидный результат
помощника). Формат ошибки: {"error":"сообщение"}. Все API поддерживают OPTIONS,
CORS Access-Control-Allow-Origin: *. Запросы используют подготовленные SQL-выражения.

## Черновики и уточняющие вопросы

- `POST /api/tasks.php`: `{"raw_description":"Нужен прогноз спроса для кафе"}` → `{"task_id":6}`.
- `GET /api/tasks.php?id=6`: черновик. Без id — список всех черновиков/задач, новые первыми.
- `GET /api/questions.php?task_id=6`: минимум три вопроса, provider и rating_details.
- `POST /api/questions.php`: `{"task_id":6,"card_id":6}` — вопросы по текущей карточке;
  card_id необязателен, принадлежность черновику проверяется. GET поддерживает те же параметры.

Вопросы сначала относятся к пустым и неподтверждённым полям. Если все поля заполнены
и подтверждены, возвращаются три вопроса для проверки актуальности.

## Формирование и редактирование карточки

`POST /api/generate.php`:

```json
{
  "task_id": 6,
  "answers": {
    "title": "Прогноз спроса для кафе",
    "topic": "HoReCa",
    "need": "Уменьшить списания",
    "data_materials": "CSV продаж за шесть месяцев",
    "expected_result": "Прототип прогноза на завтра"
  }
}
```

Ответ: `{"provider":"local_stub","card_id":6,"card":{...},"questions":[...]}`.
Создаётся новая неопубликованная карточка с рейтингом 0 и всеми подтверждениями 0.
context по умолчанию содержит исходное описание дословно; answers.context может его
заменить. Неизвестные факты остаются пустыми. Каждый POST создаёт новую карточку.
Чтобы редактировать существующую, используйте PATCH cards.php.

`POST /api/cards.php` по-прежнему создаёт карточку напрямую: `{"task_id":6}` плюс
любые из 11 текстовых полей. Подтверждения, рейтинг и публикация с клиента не принимаются.
`GET /api/cards.php?id=6` возвращает карточку и rating_details.

`PATCH /api/cards.php`:

```json
{"id":6,"field":"data_materials","value":"CSV продаж за шесть месяцев","confirmed":1}
```

Семь оцениваемых полей: context, data_materials, expected_result, success_criteria,
constraints, users, business_contact. Для них confirmed по умолчанию равен 1
(совместимость с первым API). `confirmed:0` сохраняет черновое значение или снимает
подтверждение; пустой текст разрешён только при confirmed=0. id можно передать в URL.
Дополнительно редактируются title, topic, need, interaction_format; у них нет отдельного
confirmed и дополнительных баллов. Потребность также должна быть отражена в context,
а порядок обратной связи — в business_contact, чтобы критерии рейтинга были содержательными.

Любое фактическое изменение карточки снимает её с публикации до повторной проверки.
Повторный PATCH с тем же текстом и подтверждением публикацию не меняет.
Рейтинг, текст и подтверждение обновляются атомарно.

## Рейтинг

Баллы начисляются только за непустой текст с confirmed=1: context=20,
data_materials=20, expected_result=15, success_criteria=15, constraints=10,
users=10, business_contact=10. Уровни: 0–39 «проект», 40–69 «в работе»,
70–89 «готово», 90–100 «приоритет».

calculateRating() сохраняет контракт `{rating, level}`. Дополнительный ratingDetails()
и поле ответа rating_details содержат breakdown (вес, начисленные баллы, заполненность,
подтверждение) и missing_fields (причина, действие, потенциальные баллы).

## Ручная публикация и каталог

`PATCH /api/publish.php`: `{"card_id":6,"published":1,"confirmed":1}`.
confirmed означает, что человек просмотрел и подтвердил карточку целиком для публикации.
Он не меняет отдельные подтверждения полей и не добавляет баллы. Требуются непустые
title и context. Порог рейтинга отсутствует: публикация разрешена даже при 0 баллов.
Снять с публикации: `{"card_id":6,"published":0}`. Статус исходной задачи обновляется
в той же транзакции: published, если есть хотя бы одна её опубликованная карточка.

`GET /api/catalog.php?sort=rating&topic=образование&level=приоритет`.
Только published=1, по умолчанию сортировка rating DESC, id ASC. Фильтры сочетаются.
topic ищет подстроку в title, topic, need и шести содержательных полях карточки,
без контакта бизнеса; поиск регистронезависимый, включая кириллицу.
level — точное русское название уровня. Кодируйте параметры URL.
В новой демо-базе опубликованы карточки с рейтингами 20, 40, 70, 90, 100.

## Команды, предложения и ручное решение

- `POST /api/teams.php`: `{"name":"AI Team","interests":"EdTech","skills":"NLP","technologies":"Python, PHP"}` → team_id.
- `GET /api/teams.php`: список команд.
- `POST /api/proposals.php`: `{"card_id":6,"team_id":1,"solution_idea":"Прогноз по дням недели","plan":"Анализ, прототип, проверка","prototype_link":"","deadline":"2026-10-15"}` → proposal_id.
- `GET /api/proposals.php?card_id=6`: предложения по карточке с chosen и status.

Предлагать решение можно любой опубликованной карточке независимо от рейтинга.
Количество предложений не ограничивается. Ссылка — HTTP/HTTPS или пустая строка;
deadline — существующая дата YYYY-MM-DD. Начальное состояние pending, chosen=0.

`PATCH /api/choose.php`: `{"proposal_id":6,"decision":"accepted"}`.
accepted — принять (chosen=1); rejected — отклонить (chosen=0); pending — отменить
решение (chosen=0). Без decision сохраняется старый вызов «принять» по proposal_id.
Решения по другим предложениям НЕ сбрасываются: бизнес может выбрать несколько команд.
Любое изменение решения — только явный вызов этого API; рейтинг и помощник не выбирают команды.

## Локальный помощник

ai_helper.php — детерминированная заглушка, разрешённая ТЗ при недоступности внешнего AI.
Это не внешняя языковая модель и не обучение собственной модели. provider всегда local_stub.
Промпт и контракт будущего подключения: prompts/card_assistant.txt.
Результат проверяется до вставки в БД: структура, количество и поля вопросов,
строковые значения и точное совпадение фактов с исходным описанием/ответами. Невалидный
результат даёт 502 и не сохраняется. Входные неверные типы/поля дают 400.

## Демонстрационный сценарий

1. Создать слабый черновик через tasks.php.
2. Получить вопросы через questions.php.
3. Передать ответы в generate.php и получить неопубликованную карточку с рейтингом 0.
4. Подтвердить поля через PATCH cards.php, показать начисленные и недостающие баллы.
5. Опубликовать через publish.php, найти карточку в каталоге.
6. Отправить предложения от двух команд.
7. Вручную принять оба, затем отклонить одно: другое остаётся принятым.

## Границы этого этапа и фронтенд

Существующие JS-файлы frontend не изменялись: они пока используют LocalStorage.
Регистрация/вход, разграничение доступа, чат, уведомления, баллы командам за прогресс
и обучение собственной модели остаются отдельными этапами. API пока не проверяет
личность/роль отправителя и владельца карточки. Для публичного запуска потребуются
авторизация и исключение database.sqlite, data/, prompts/, lib/ из статической раздачи.

Для frontend соответствия полей: industry→topic, data→data_materials,
result→expected_result, success→success_criteria, contact→business_contact,
format→interaction_format, score→rating. Backend возвращает целочисленные id;
задача (task_id) и карточка (card_id) — разные сущности. В предложении timeline
нужно преобразовать в конкретную дату deadline, '#' не является допустимой ссылкой.
Рейтинг и решения следует брать из API, не рассчитывать по длине текста на клиенте.
