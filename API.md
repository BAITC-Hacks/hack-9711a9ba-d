# AI Sana: PHP + SQLite API

## Запуск

Требуются PHP 7.3+ и расширение pdo_sqlite. В терминале из корня проекта:

```powershell
php seed.php
php -S localhost:8000
```

Если PHP не добавлен в PATH, используйте установленный XAMPP:

```powershell
& 'C:\xampp\php\php.exe' seed.php
& 'C:\xampp\php\php.exe' -S localhost:8000
```

Откройте http://localhost:8000/api/catalog.php?sort=rating.
Существующий index.html использует LocalStorage; подключение его к API требует отдельного изменения фронтенда.

seed.php запускается только через CLI, создаёт схему и добавляет по 5 записей в каждую таблицу в одной транзакции. Если хотя бы одна таблица уже содержит данные, вставка пропускается. Повторный запуск не изменяет данные и ручной выбор. database.sqlite создаётся рядом с db.php. Схема и JSON должны находиться рядом с seed.php в указанной ниже структуре.

## Контракт

Тела POST/PATCH — JSON-объекты, заголовок Content-Type: application/json.
Ответы GET списков — JSON-массивы, GET по id — объект. Создание возвращает HTTP 201 с идентификатором, PATCH — обновлённый объект, ошибки — {"error":"сообщение"}.
Коды: 400 — некорректный запрос, 404 — запись не найдена, 405 — метод не поддерживается, 500 — внутренняя ошибка. OPTIONS возвращает JSON с CORS-заголовками без подключения к БД.

ИИ-помощник также возвращает 422 при некорректных ответах бизнеса или обнаружении
персональных данных/формулировок выбора команд. Ошибки внешнего AI API включают
локальный fallback. Настройка, контракты и ограничения: [AI_HELPER.md](AI_HELPER.md).

| Файл | Метод | Параметры / JSON |
|---|---|---|
| api/tasks.php | POST | `{"raw_description":"Нужен прогноз продаж"}` → `{"task_id":6}` |
| api/tasks.php | GET | `?id=6` |
| api/cards.php | POST | `{"task_id":6}` → `{"card_id":6}`; дополнительно можно передать семь текстовых полей |
| api/cards.php | POST | `{"action":"questions","task_id":6}` → `{"task_id":6,"questions":[{"field":"context","question":"... ?"}, ...]}`; минимум 3 вопроса |
| api/cards.php | POST | `{"action":"build","task_id":6,"answers":{"users":"Управляющий магазина."}}` → `{"card_id":6}`; структурирование и проверка перед сохранением |
| api/cards.php | PATCH | `{"id":6,"field":"context","value":"Прогноз продаж магазина"}`; id также можно передать через `?id=6` |
| api/cards.php | GET | `?id=6` |
| api/catalog.php | GET | `?sort=rating&topic=склад&level=приоритет` |
| api/teams.php | POST | `{"name":"AI Team","interests":"EdTech","skills":"NLP","technologies":"Python, PHP"}` → `{"team_id":6}` |
| api/teams.php | GET | Без параметров |
| api/proposals.php | POST | `{"card_id":3,"team_id":6,"solution_idea":"Поиск по FAQ","plan":"Анализ, прототип, проверка","prototype_link":"","deadline":"2026-10-15"}` → `{"proposal_id":6}` |
| api/proposals.php | GET | `?card_id=3` |
| api/choose.php | PATCH | `{"proposal_id":6}` — явное ручное действие бизнеса |

В PATCH карточки разрешены только context, data_materials, expected_result, success_criteria, constraints, users, business_contact. Непустое значение сохраняется вместе с подтверждением и пересчётом рейтинга в одной транзакции. При создании все подтверждения равны 0, даже если передан текст. Клиент не может напрямую задавать рейтинг, подтверждения или chosen.

topic — регистронезависимый поиск подстроки по шести содержательным полям карточки (без контакта бизнеса); поддерживается кириллица. Отдельной колонки topic в исходной схеме нет. level — точное значение: проект, в работе, готово, приоритет. Сортировка: rating DESC, id ASC. По умолчанию id ASC. Фильтры можно сочетать; строковые значения в URL следует кодировать.

В seed карточки имеют рейтинги 20, 40, 70, 90, 100. Карточка 1 не опубликована, 2–5 опубликованы. Пять исходных tasks сохранены как draft по условию задания. Новые карточки также не опубликованы: отдельный API публикации в шагах 4–10 не задан. Пересчёт рейтинга не публикует карточку автоматически.

Все предложения изначально chosen=0. Только choose.php устанавливает chosen=1; изменение выбора сбрасывает другие предложения той же карточки, не затрагивая остальные карточки.

В этой версии нет аутентификации и проверки принадлежности карточки бизнесу: choose.php выражает ручное действие через явный запрос, но не проверяет роль отправителя. Перед публичным запуском потребуется авторизация. Встроенный сервер PHP предназначен для локальной разработки; database.sqlite и seed-файлы не должны быть доступны как статические файлы на публичном сервере.
