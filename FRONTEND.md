# AI Sana — frontend MVP

Клиент сделан на чистых HTML, CSS и JavaScript. Он использует JSON API через `fetch()` и не содержит захардкоженных задач, команд или предложений.

## Папки `/frontend`

```text
frontend/
├── index.html
├── business/
│   ├── new-task.html
│   ├── questions.html
│   ├── card.html
│   └── proposals.html
├── team/
│   ├── profile.html
│   ├── catalog.html
│   ├── task-view.html
│   └── my-proposals.html
├── css/
│   └── style.css
└── js/
    ├── api.js
    ├── ui.js
    ├── navigation.js
    ├── ratings.js
    ├── business.js
    ├── catalog.js
    ├── team.js
    └── proposals.js
```

`ratings.js` — переиспользуемый индикатор рейтинга, бейджа и уровня. Цвета: серый «Проект», жёлтый «В работе», синий «Готово», зелёный «Приоритет».

## Полный сценарий

1. `index.html`: выбор роли сохраняется в `localStorage`.
2. Бизнес создаёт черновик на `business/new-task.html`.
3. `business/questions.html` показывает не менее трёх вопросов, переданных AI-модулем backend вместе с черновиком. Если вопросов нет или их меньше трёх, страница показывает ошибку контракта и не подставляет выдуманные вопросы.
4. Ответы сохраняются как неподтверждённые поля карточки. На `business/card.html` бизнес редактирует и подтверждает поля отдельно. После каждого PATCH карточка перечитывается, а рейтинг обновляется без перезагрузки.
5. Переиспользуемый рейтинг показывает текущие баллы и уровень. Кнопка публикации становится доступна от 40 баллов.
6. Публикация переводит бизнес на страницу сравнения предложений.
7. Команда создаёт профиль и получает список опубликованных карточек в `team/catalog.html`, с фильтрами темы/уровня и сортировкой по рейтингу.
8. В `team/task-view.html` команда читает карточку, заполняет идею, план, ссылку и срок и отправляет предложение.
9. Бизнес вручную сравнивает отклики на `business/proposals.html`. Автовыбора и рекомендательной подсветки нет. После явного нажатия показывается выбранная команда.
10. Команда проверяет статусы на `team/my-proposals.html`.

## Запуск

Если папки `frontend/` и `api/` находятся внутри этого проекта, из корня проекта запустите:

```bash
php -S localhost:8000 -t .
```

Откройте `http://localhost:8000/frontend/`. Если backend размещён в другом месте, задайте `window.API_BASE` до подключения `js/api.js` в HTML страниц (например, `https://server.example/api`). Открывать через `file://` нельзя: браузеру нужен HTTP-сервер для `fetch()`.

## API, используемый клиентом

- `POST /api/tasks.php` `{raw_description}`; ответ `{task_id}`.
- `GET /api/tasks.php?id=X`; должен включать не менее трёх AI-вопросов в `questions`, `clarifying_questions` или `ai_questions`.
- `POST /api/cards.php` `{task_id}`; ответ `{card_id}`.
- `PATCH /api/cards.php` `{card_id, field, value, confirmed}`.
- `GET /api/cards.php?id=X` возвращает поля карточки, `rating`, `readiness_level` и, если опубликована, `published`.
- `POST /api/teams.php` `{name, interests, skills, technologies}`; ответ `{team_id}`.
- `GET /api/catalog.php?sort=rating&topic=X&level=Y` возвращает массив карточек (или `{cards: [...]}`).
- `POST /api/proposals.php` `{card_id, team_id, solution_idea, plan, prototype_link, deadline}`.
- `GET /api/proposals.php?card_id=X` возвращает отклики к карточке.
- `PATCH /api/choose.php` `{proposal_id}`.

### Два endpoint, которые нужно добавить на backend

В исходном перечне API не было отдельного endpoint публикации и списка откликов команды. Поэтому UI ожидает:

- `POST /api/publish.php` `{card_id}` для публикации карточки.
- `GET /api/proposals.php?team_id=X` для страницы «Мои предложения».

Пока этих маршрутов нет, соответствующие действия покажут читаемую ошибку API; frontend их не симулирует.

## Формат данных для UI

Элементы каталога желательно возвращать с `card_id`, `title`, `topic`, `context`, `rating`, `readiness_level`. В карточке поля: `context`, `data_materials`, `expected_result`, `success_criteria`, `constraints`, `users`, `business_contact`. Поле может быть строкой или объектом `{value, confirmed}`. Отклик: `proposal_id`, `team_name`, `solution_idea`, `plan`, `prototype_link`, `deadline`, `status`.

Уровни, понимаемые UI: «проект» (0–39), «в работе» (40–69), «готово» (70–89), «приоритет» (90–100). Значение и рейтинг отображаются из ответа backend.

Уровень на экране определяется границами серверного рейтинга: устаревший текстовый бейдж не может повысить готовность. Неподтверждённые правки других полей сохраняются в памяти страницы при подтверждении одного поля. Статусы предложений перечитываются из API; старый выбор в localStorage не подменяет ответ сервера.

## Проверки клиента

В корне проекта выполните `node --test tests/frontend.test.cjs`. Проверки охватывают отрицательные статусы предложений, ссылки на прототипы, границы рейтинга, ошибки JSON API, формат PATCH и существование ссылок между HTML-страницами. Они используют подставленные ответы и не заменяют проверку с настоящим PHP backend.

Дополнительно проверяются таймаут без автоматического повторения записи и сохранение других правок при подтверждении поля. Если PATCH прошёл, а чтение обновлённого рейтинга не удалось, кнопка «Обновить состояние» повторит только чтение.

Ответы на вопросы без `field` бизнес привязывает к разделу вручную. Несколько ответов для одного раздела объединяются. Незавершённые правки хранятся в sessionStorage текущей вкладки, включая ответы, которые не удалось передать серверу.

Полный код всех клиентских файлов собран в `SOURCE_CODE.md`. После изменений его можно обновить командой `node scripts/export-source.cjs`.
