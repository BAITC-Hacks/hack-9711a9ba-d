# ИИ-помощник AI Sana: шаги 1–4

Реализация: `ai_helper.php`; подключение: `api/cards.php`. PHP 7.3+ по синтаксису,
для запуска используйте поддерживаемую версию PHP. Внешний режим требует cURL;
локальный режим не требует cURL, mbstring, Composer или доступа к сети.

## Шаг 1. Функции и единый формат

```php
require_once __DIR__ . '/ai_helper.php';

$rawDescription = 'Нужен прогноз продаж магазина.';
$questions = generateQuestions($rawDescription);
// Массив из 3–7 объектов: ['field' => 'data_materials', 'question' => '... ?'].

$answers = [
    'data_materials' => 'Есть CSV продаж за 6 месяцев.',
    'expected_result' => 'Прототип прогноза на неделю.',
    'users' => 'Управляющий магазина.',
    'business_contact' => 'Отдел продаж, обратная связь раз в неделю.',
];
$cardJson = buildCardFromAnswers($rawDescription, $answers);
```

`$answers` — ассоциативный массив `поле => строка` или строка с JSON-объектом.
Ключ ответа совпадает с `field` вопроса. Неизвестные ключи, массивы вместо текста,
`null` и ответы без привязки к полям отклоняются: помощник не угадывает назначение
ответа. Каждая входная строка — UTF-8, максимум 12000 байт.

Результат `buildCardFromAnswers()` — **JSON-строка**, ровно семь строковых полей:

```json
{
  "context": "Нужен прогноз продаж магазина.",
  "data_materials": "Есть CSV продаж за 6 месяцев.",
  "expected_result": "Прототип прогноза на неделю.",
  "success_criteria": "",
  "constraints": "",
  "users": "Управляющий магазина.",
  "business_contact": "Отдел продаж, обратная связь раз в неделю."
}
```

Оба режима сохраняют ответы дословно, обрезая пробелы по краям. Если ключ `context`
отсутствует, туда переносится весь черновик. Отдельный ответ `context` заменяет
черновик; даже явно переданная пустая строка сохраняется. Остальные пропуски — `""`.
Черновик не используется для догадок о значениях остальных полей.

## Шаг 2. Внешний API и fallback

По умолчанию API выключен. Для включения задайте **переменную окружения PHP-процесса**
`AI_API_KEY`, при необходимости `AI_MODEL` (по умолчанию `gpt-4o-mini`). Ключ не
передаётся фронтенду, не сохраняется в коде и не выводится в журнал. `.env` автоматически
не загружается. После изменения окружения перезапустите PHP-сервер.

Для проверки локального режима в PowerShell:

```powershell
$env:AI_API_KEY = ''
php -S localhost:8000
```

`aiRequestJson()` делает cURL POST на `https://api.openai.com/v1/responses`:

```php
$key = trim((string) getenv('AI_API_KEY'));
$payload = [
    'model' => trim((string) getenv('AI_MODEL')) ?: 'gpt-4o-mini',
    'instructions' => $instructions,
    'input' => aiJson($input),
    'text' => ['format' => ['type' => 'json_object']],
    'max_output_tokens' => 4096,
    'store' => false,
];
```

Промпты прямо требуют чистый JSON без Markdown и пояснений, запрещают новые факты,
личные данные и выбор команд. Входные описания обозначены как данные, а не инструкции.
JSON mode применяется согласно [официальной документации OpenAI](https://developers.openai.com/api/docs/guides/structured-outputs).
Он не гарантирует соответствия нашей схеме: результат дополнительно проверяется в PHP.

Тайм-аут подключения — 3 секунды, всего запроса — 15 секунд, ответ ограничен 256 КиБ.
TLS-проверка включена; переходы по редиректам выключены. Нет ключа/cURL, сеть недоступна,
HTTP 401/429/5xx, отказ модели, незавершённый ответ, неверный JSON, неправильные поля или
провал валидации → локальный fallback. Формат публичных функций не меняется.

Локальная генерация ищет ключевые слова в предложениях длиной от четырёх слов;
фразы неопределённости вроде «пока не знаем» не считаются заполнением. Сначала идут
вопросы по отсутствующим полям. Если таких полей меньше трёх, добавляются уточнения
по уже упомянутым полям. Для продаж и обращений/ботов есть отдельные вопросы о данных
и проверке результата. Это эвристика полноты, а не подтверждение фактов.

Fallback сборки переносит ответы по ключам в заранее созданные семь пустых полей.
Он проходит тот же валидатор, что и ответ API. Если сам ввод содержит запрещённые
данные, выбрасывается `InvalidArgumentException`; эти данные не отправляются провайдеру.

## Шаг 3. Проверка результата

```php
$validation = validateAiOutput($cardJson, $rawDescription, $answers);
if (!$validation['valid']) {
    // errors содержит объяснения, но не повторяет обнаруженные личные данные.
    throw new InvalidArgumentException(implode(' ', $validation['errors']));
}
```

Первый аргумент принимает JSON-строку или PHP-массив. Результат всегда имеет вид
`['valid' => bool, 'errors' => string[]]`. Вызов `validateAiOutput($output)` допустим,
но **отклоняет результат без независимых исходников**: из одной карточки нельзя
установить, какие факты сообщил бизнес. Источники передаются сервером, отдельно от
ответа модели; скрытого состояния между запросами нет.

Проверки:

1. Ровно семь предусмотренных ключей, только строковые значения, допустимые UTF-8 и длина.
2. Все слова и числа результата должны пересекаться с лексикой **того же исходного поля**.
3. Дополнительно полное дословное совпадение с источником после нормализации пробелов.
   Это блокирует удаление отрицаний, перестановку чисел, выдуманные сроки и перенос фактов
   между полями. Свободное перефразирование намеренно не поддерживается.
4. Запрещены сочетания слов о командах/исполнителях с выбором, рекомендацией, рейтингом,
   назначением и победой; явные названия команд и ключи `team_id`, `proposal_id`, `chosen`.
   Проверяется и объединённый текст полей. Простое упоминание работы студентов допустимо.
5. Эвристики email, телефонов, паспортных реквизитов, ИИН, платёжных номеров, имён/инициалов,
   подписанных дат рождения, адресов, диагнозов, паролей и идентификаторов аккаунтов.
   Скрытые управляющие символы отклоняются.

`business_contact` в публичной ИИ-карточке означает **роль/отдел и частоту обратной связи**.
Например: «Отдел продаж, консультация раз в неделю». Email, телефон и ФИО не допускаются.

Ограничения MVP: регулярные выражения не распознают все формы личных данных и все
завуалированные рекомендации. Возможны ложные срабатывания на названия из двух слов
с заглавными буквами, длинные числовые значения и соседство слов о командах и выборе.
Проверки не заменяют проверку человеком перед публикацией. Старые ручные POST/PATCH
и существующие seed-данные не проходят через ИИ-помощник и этими правилами не меняются.

## Шаг 4. Точка интеграции в api/cards.php

```php
require_once __DIR__ . '/../ai_helper.php';

// После создания tasks: POST cards.php, action=questions.
$questions = generateQuestions($task['raw_description']);

// После ответов бизнеса: POST cards.php, action=build.
$cardJson = buildCardFromAnswers($task['raw_description'], (array) $data['answers']);
$fields = json_decode($cardJson, true, 32, JSON_THROW_ON_ERROR);
// Далее существующая INSERT в cards. *_confirmed, rating, published задаёт БД.
```

Порядок запросов:

1. `POST /api/tasks.php` с `{"raw_description":"Нужен прогноз продаж магазина."}`
   → HTTP 201, `{"task_id":6}`. Сохраняется черновик.
2. `POST /api/cards.php` с `{"action":"questions","task_id":6}`
   → HTTP 200, `{"task_id":6,"questions":[{"field":"context","question":"... ?"}, ...]}`.
   Карточка пока не создаётся. Фронтенд связывает ответы с ключами `field`.
3. `POST /api/cards.php` с `{"action":"build","task_id":6,"answers":{"users":"Управляющий магазина."}}`
   → HTTP 201, `{"card_id":6}`. `answers` обязательно является объектом; `{}` допустим.
4. `GET /api/cards.php?id=6` получает сохранённую карточку. На создание подтверждения
   всех полей равны 0, рейтинг равен 0, публикация выключена. Бизнес редактирует и
   подтверждает поля через существующий `PATCH /api/cards.php`.

Исходное описание берётся из `tasks` по `task_id`, клиент не подменяет его в запросе
сборки. Вызов API происходит до транзакции записи SQLite. Валидация происходит внутри
`buildCardFromAnswers()` до возврата JSON; при ошибке карточка не вставляется.
Ошибочный формат запроса → 400, неизвестная задача → 404, небезопасный/невалидный
ввод помощника → 422 с `{"error":"..."}`. Проблемы провайдера сами по себе не вызывают 500.

Прежние ручной `POST {"task_id":6,...}`, `GET`, `PATCH` остаются совместимыми.
Помощник не читает список команд и не вызывает `choose.php`. Только отдельное ручное
действие бизнеса может выбрать предложение. Повторный `build` создаёт новую карточку,
как прежний POST; обновление существующей выполняется через PATCH.

Фронтенд проекта пока использует LocalStorage: его переключение на эти запросы
не входит в шаги 1–4. Рейтинг и публикация не запускаются автоматически из ИИ-помощника.

## Проверка

```powershell
php -n tests/ai_helper_test.php
php -n tests/ai_transport_test.php
python tests/ai_api_test.py --php php
```

Первые два сценария не обращаются в сеть. Второй подменяет границу cURL и проверяет
успешные ответы, ошибки HTTP, отказ, повреждённый JSON, ограничение размера и fallback.
HTTP/SQLite-тест поднимает PHP на localhost и копирует проект во временную папку;
рабочая база не изменяется. Для него нужны Python 3 и расширение PHP `pdo_sqlite`.
Реальный платный запрос требует действующего `AI_API_KEY` и отдельно доступного API.
